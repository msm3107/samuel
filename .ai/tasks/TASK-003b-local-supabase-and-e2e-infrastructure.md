# TASK-003b — Local Supabase and end-to-end infrastructure

> **Status: draft, awaiting project-owner approval.** Do not start until it is
> approved.

## Objective

Make a real Supabase instance available locally and in CI, so Phase 1's exit
criterion — sign-in works end to end against local Supabase — is proven by
automated tests rather than by stubs and manual notes.

## Owner agent

Database, with Testing for the CI job.

## Dependencies

TASK-002. Locally, a working Docker Desktop on the developer machine (owned by
the project owner).

## Allowed files

- supabase/config.toml
- supabase/seed.sql (comments only; no data until a schema exists)
- .github/workflows/e2e.yml (new workflow; `ci.yml` and `security.yml` are not
  modified)
- package.json, pnpm-lock.yaml (the `supabase` CLI as a pinned devDependency,
  and new scripts only). TASK-003 also edits these for Playwright: the two
  tasks must not run concurrently, or must land in either order with a lockfile
  refresh. The orchestrator sequences them; TASK-003a does not touch them.
- vitest.supabase.config.ts
- tests/supabase/** (named `*.supabase.ts`, not `*.test.ts`)
- scripts/local-env.mjs
- .env.example (comments only)
- CONTRIBUTING.md (local setup section)

## Forbidden files

- supabase/migrations/** (no schema in this task)
- ci.yml, security.yml
- vitest.config.ts
- lib/**
- app/**
- proxy.ts

## Invariants

- No real credentials are committed.
  - Google OAuth client id and secret are read with `env()` in
    `config.toml`, and the provider stays disabled when they are absent.
  - Local anon and service keys are generated by the CLI and never committed.
- Auth redirect allowlist:
  - `site_url` is `http://localhost:3000`.
  - `additional_redirect_urls` lists exact URLs only (`/auth/callback` on
    localhost and 127.0.0.1). No wildcards.
- Auth rate limits (email sends, OTP verifications, token refreshes) are set
  explicitly in `config.toml`, not left implicit.
- `pnpm test` remains runnable without Supabase, and CI's existing jobs are
  unchanged. The default Vitest config includes `tests/**/*.test.ts(x)`, so
  real-Supabase files are named `*.supabase.ts` instead and are picked up only
  by `vitest.supabase.config.ts` via `pnpm test:supabase`. This keeps the
  isolation without editing `vitest.config.ts`, which stays forbidden here.
- No production or hosted project is linked. Nothing in this task can target a
  remote database.
- The seed contains no personal data.

## Acceptance criteria

- `supabase start` and `supabase db reset` succeed from a clean checkout.
- `pnpm test:supabase` proves against the real local instance that:
  - a generated magic link, exchanged through `/auth/callback`, yields a
    session that `requireSession()` accepts
  - a signed-out (revoked) session is rejected
  - the proxy refreshes an expired access token
- The new `e2e.yml` workflow starts Supabase, runs `pnpm test:supabase`, and
  passes on a pull request.
- `CONTRIBUTING.md` documents local setup, including where local keys come
  from.

## Required tests

- supabase: magic link to callback to `requireSession()`, end to end
- supabase: revoked session is rejected
- supabase: expired access token is refreshed through the proxy
